# CS-5: X-Ray item addition

`XRayAddWriter` adds actor inventory items by cloning a serializer-family
template already present in the registry. The original trilogy releases are
`verified`; Enhanced Edition releases are `experimental`, matching the Python
capability registry.

The writer accepts catalog keys and the `inventory` destination. It clones
ammo into one stack and writes the requested count into both STATE and UPDATE;
other supported families create one registry record per requested item. The
writer refuses missing catalog keys, unknown serializer families, missing
templates, stale source hashes, mixed edits, non-inventory destinations, and
ammo counts above catalog `max_stack`.

When a clone exposes a recognized X-Ray upgrade vector, the writer clears it.
It resets a recognized `SInvItemPlace` to ruck while preserving its other
bits, and handles the Clear Sky one-byte place immediately after the client
data count (`1` slot, `2` belt, `3` ruck). Unknown client data remains intact.
The output is reparsed to confirm the release, parent, handles, upgrades, and
ammo counts.

Synthetic fixtures generated by `tools/generate_xray_add_fixtures.py` from the
Python repository compare the compressed output and unpacked bytes for outfit
and ammo additions across all six supported releases. Tests include the
equipped Call of Pripyat template regression. These fixtures do not provide
live game load/save evidence.
