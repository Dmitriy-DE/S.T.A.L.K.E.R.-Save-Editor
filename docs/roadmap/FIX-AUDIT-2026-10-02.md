# Game fixes added on 2026-10-02 — what each one touches

One record per fix: the game function it belongs to, who uses that function, what changes for the player, and how far
the logic was checked. Nothing here was run in a game; "checked" always means reading the retail files (and the SRP,
ZRP and Enhanced Edition versions where they exist).

Depth of the check:

- **A** — the whole function was read: every caller and every reader of the changed value, including save and load.
- **B** — the faulty lines and their direct callers were read; the fault is local (a typo, a missing variable, a wrong sign).
- **C** — the remedy follows SRP or GSC; I understand what it does but not every consequence.
- **D** — my own design for a path that used to crash or corrupt; its behaviour in play is unobserved.

## What this audit changed

- Nothing was removed. The two **D** entries and the three **C** entries without an Enhanced Edition counterpart
  (`cs.save.flea-market-basement-object`, `cs.logic.attack-squads-skip-post-jobs`, the 'idle' part of `cs.crash.sim-combat`)
  are the ones to watch first in a play test.
- Re-reading for this table confirmed three things that were only assumed: job conditions (`suitable`) receive the
  server object, which the new attacking-squad condition needs; the squad-hostility check is safe when the squad no
  longer exists; `main_ps_2_0` in `r2/vert.ps` is the engine's own entry-point convention, so SRP's change there is not a fix.

## Assets and the engine

- **SRP's sounds, textures and models.** Compared with the retail archives: 26 files replace existing ones (25 weapon
  sounds re-cut for SRP's own weapon configs, the Limansk bridge model); the other 17 are new files that no retail
  config refers to (new hand and suit models, sounds and icons for SRP's changed configs). Only the bridge model
  repairs a retail fault (NPCs failing to cross). A binary file needs the content store, which has no download source
  since the pack downloader was removed: that is a hosting decision, not a catalogue entry.
- **Wet surfaces shaders** (`rain_patch_normal.ps`, `rain_apply_gloss.ps`): SRP re-tunes the effect and changes a
  texture type; without rendering it there is no way to tell a repair from a different look.
- **Engine binaries.** The catalogue can already carry same-length binary patches bound to one file hash (used for
  `all.spawn`). What is missing is not the mechanism but the patches: each engine fault needs its own reverse
  engineering of the retail `xrGame.dll` / `xrCore.dll`, and none of the sources contains ready ones for the Steam builds.
